# Единый блок акцентного текста

Дата: 27.11.2026. Статус: требования согласованы, реализация не начата.
Публикация этого ТЗ не разрешает выкладку, изменение данных или перепубликацию страниц.

## 1. Охват

У перечисленных секций единый редакторский контракт: два текстовых поля и выбор оформления.
Ключи секций, позиции в шаблоне, права доступа и возможность отключения не меняются.

| Страница | Секции | Видимость по действующей схеме |
| --- | --- | --- |
| [Главная](home-page-structure-2026-08-05.md) | `home_accent_text` | Обязательная, не отключается |
| [Практика](practice-page-structure-2026-06-13.md) | `practice_intro_text`, `practice_reviews_text`, `practice_price_text` | Независимые отключаемые секции; по умолчанию включена только первая |
| [Услуга](service-page-structure-2026-06-16.md) | `service_accent_text_1`, `service_accent_text_2`, `service_accent_text_3`, `service_price_text` | Независимые отключаемые секции; по умолчанию включены три Accent text |
| [Проблема](problem-page-structure-2026-06-15.md) | `problem_accent_text_1`, `problem_accent_text_2` | Независимые отключаемые секции, обе включены по умолчанию |
| [Лицензия](license-page-backend-contract-2026-09-27.md) | `license_model` («Ліцензійна модель») | Обязательная, не отключается |
| [Интент](intent-page-family-requirements-2026-07-30.md) | `intent_intro_text` | Отключаемая, по умолчанию включена |

Все правила действуют для UA, RU и EN. Для `intent_intro_text` контракт в CMS такой же, как у
остальных. Когда публичная страница интента будет выводить секции, она использует общий рендерер блока
и его видимость. ТЗ не требует отдельного рендерера или досрочного запуска страниц интентов.

Вне охвата: фиксированное Intro главной, заголовки других блоков и Hero, Team CTA, `home_price_text`,
глобальный прайс и списки цен/отзывов. `*_price_text` в таблице — отдельные поясняющие секции.

## 2. Поля и проверка

| Поле | Что видит редактор и посетитель | Правило |
| --- | --- | --- |
| `title` | «Заголовок», небольшая строка над основным текстом | Необязательный обычный текст, максимум **40** символов |
| `lead` | «Основний текст», крупный текст блока | Обязательный обычный текст, максимум **150** символов |
| `variant` | «Оформлення», выбор из общего каталога | Целое число **1–6**; без явного выбора применяется прежний вариант по умолчанию |

- Два текстовых поля не поддерживают разметку, форматирование или списки. Site-front выводит
  строку как текст целиком, с обычным переносом по ширине; не разбирает HTML и не берёт только
  первый фрагмент. Пустой заголовок не создаёт пустую строку или отступ.
- Для проверки и сохранения убираем пробелы по краям. Внутренние пробелы считаем в длину,
  текст из одних пробелов считается пустым. CMS-back и CMS-front считают одинаково: в
  кодовых точках Unicode, не в байтах и не по длине JSON.
- Ровно 40/150 допустимо. Превышение, пустой `lead`, неверный тип или номер оформления —
  ошибки соответствующего поля, а не предупреждения. Не обрезать текст автоматически.
  CMS-front даёт обратную связь рядом с полем, CMS-back принимает окончательное решение.
- Правила действуют при сохранении новой версии и явной проверке секции. Для проверки
  публикации страницы проверяем те версии включённых блоков, которые войдут в снимок.
  Скрытая секция не блокирует публикацию страницы и не создаёт рабочих замечаний об актуальности;
  её новую версию можно подготовить и проверить, не включая блок.
- Для старых текстов нет исключения: если при следующей проверке сохранённого текста он выходит
  за 40/150 или основной текст пуст, это ошибка. Сохранение другой секции не запускает проверку
  этого блока. Массовую перепроверку из-за внедрения не запускаем.

## 3. Оформление и наследование

- Один каталог из шести оформлений для всех строк таблицы и языков. Сохраняем только номер
  `variant`. Галерея CMS использует общие статические превью; загрузки на страницу или в
  медиатеку нет. На сайте оформление рисует общий компонент; PNG-превью CMS не нужны посетителю.
- Скин — весь вид блока, не только фон. №6 сохраняет нынешнюю геометрию, размеры, типографику
  и акцент «Ліцензійної моделі» и доступен везде. Каталог превью и фактический вид должны совпадать.
- Существующий явный выбор не меняем. Если выбор не задан, сохраняются прежние значения:
  №6 для «Ліцензійної моделі», номер позиции для нумерованных Accent text услуг и проблем,
  №1 для остальных. Редактор показывает фактический вариант; открытие формы само его не записывает.
- Выбор скина независим для каждой секции и каждого языка. Переводить номер скина или синхронизировать
  выбор между UA/RU/EN не нужно. Общая [видимость языковой группы](https://github.com/alekseyactum/CMS-develop/blob/1e5065cc916e2d1f939ea85a06a2e975d0294e71/docs/section-visibility-locale-group-specification-2026-11-26.md)
  не делает тексты или оформление общими и не меняется этим ТЗ.
- На региональных страницах практик, услуг и проблем `title` наследуется из национальной
  страницы **того же языка**, без локального переопределения. `lead` и `variant` можно независимо
  наследовать или переопределять. Не копируем унаследованные поля в локальный слой и не
  подставляем другую локаль. Остальные правила владения и наследования сохраняются.

## 4. Старые версии и порядок перехода

1. При чтении старой версии для редактора берём весь текст из прежнего `lead` в порядке
   абзацев и текстовых фрагментов. Убираем форматирование, но не теряем текст. Учитываем
   старый источник `paragraphs`, если текст хранился только в нём. Для `license_model`
   показываем `accentText` как `title`, `description` как `lead`, оформление №6.
   Само открытие, чтение истории или проверка ничего не записывает.
2. При явном Save сохраняем новую версию в едином формате: `title`, строковый `lead`, `variant`.
   Для наследуемых секций преобразуем и проверяем итоговое содержание, сохраняя границу
   между источником и локальными переопределениями. Не переписываем старые версии.
3. Старый опубликованный снимок сайт отображает по прежним правилам. Деплой не показывает
   автоматически ранее невидимые части старого rich text и не меняет вид лицензии. Весь
   текст нового формата появляется на сайте после обычной явной публикации новой версии.
   Preview новой версии использует новый рендер.
4. До начала записи нового формата проверяем, что CMS-front и site-front умеют читать обе
   формы. Порядок выкладки согласуем отдельно. Пакетной миграции, обрезки, массовой
   перепубликации, изменения видимости или включения кэша в задаче нет.

## 5. Задачи и приёмка

| Исполнитель | Что сделать |
| --- | --- |
| CMS-back | Общая схема слотов из таблицы и общий валидатор 40/150 и 1–6. Совместимое чтение старых версий, новые записи только при явном сохранении. Проверить авторинг, диагностику, публикацию и наследование. |
| CMS-front | Три одинаково названных поля UA/RU/EN, простой ввод текста, счётчики и ошибки у полей, одна галерея на шесть вариантов. Уважать readonly-наследование; не сбрасывать локальные значения и не писать при открытии. |
| site-front | Общий рендерер нового блока с шестью оформлениями. Сохранить совместимость старых снимков, выводить весь новый текст, не показывать выключенные секции. Для интентов применять его в штатном выводе секций по готовности страницы. |

Приёмка на фикстурах:

- Для каждой группы слотов: пустой заголовок допустим; 40/150 принимаются, 41/151 отклоняются
  у конкретного поля; пустой и пробельный основной текст отклоняется. Проверить кириллицу,
  латиницу, символ вне BMP, внутренние пробелы, номера 1 и 6 и отказ для 0, 7 и дробного числа.
- Один и тот же каталог в разных секциях. UA и RU сохраняют разные выбранные скины, EN
  не меняется. Регион не меняет заголовок, но может менять и возвращать к наследованию
  `lead` и `variant` независимо; источники других языков не используются.
- Старый rich text из нескольких фрагментов и старый `license_model` читаются целиком в
  редакторе; старый длинный текст при проверке даёт ошибку. Save корректной новой версии
  не меняет старый снимок; после его штатной замены весь новый текст виден, №6 выглядит
  как прежний блок лицензии. Проверить preview и историю.
- Отключённый блок отсутствует в публичной сборке, его черновик не включает блок,
  его ошибки не блокируют выпуск страницы без него. Обязательные блоки остаются
  обязательными. В CMS у интента те же поля и проверки; его маршрут не запускается
  этой задачей. Проверка на рабочих данных не редактирует и не публикует страницы.
